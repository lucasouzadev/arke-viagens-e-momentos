# CHANGELOG-GUIDE — Public notes anyone understands

- Two situations, never mixed: **project progress** (nothing released) vs **released to users** (version, real date, confirmed platforms). Work in a PR, internal beta or prototype is never written as available.
- Plain everyday language in the owner's language; one idea per sentence; subject + verb + benefit ("You can now save places before creating a trip").
- No jargon: refactor, backend, CI, PR, hotfix, deploy, migration.
- No invented metrics, performance, security or privacy promises.
- No personal identifiers, private content, location traces.
- Internal/agent notes go to an `Unreleased` section or the handoff, not to the public text.
