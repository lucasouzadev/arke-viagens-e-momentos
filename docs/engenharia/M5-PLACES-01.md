# M5-PLACES-01 — Adicionar, revisar e guardar ideias de lugares

Data: 01/11/2026. Estado: implementado e verificado no PR #2, sem merge. M5, branch chore/development-kickoff, PR #2.

Autorização: responsável autorizou os próximos fluxos após a entrega do puxador. Escopo adotado: primeiro fluxo completo de adicionar lugar, revisão, voltar para editar, cancelamento com confirmação, coleção pessoal local e exclusão confirmada. A preferência opcional apresentada no chat foi nome/endereço escrito/nota e armazenamento no aparelho, para funcionar nas duas plataformas sem chave Google. Esse padrão mínimo não aprova schema M3, contas, compartilhamento, sync ou Pin geográfico.

Ideia escrita não é Pin: sem coordenadas, geocoding, GPS, viagem, foto ou rede nova. Mapas existentes não recebem os endereços. Nome obrigatório até 100 escalares Unicode, endereço/referência obrigatório até 240 e nota opcional até 1000; remover espaços externos sem truncar texto. Identidade estável do rascunho evita duplicar o mesmo envio; ideias distintas com texto igual continuam possíveis.

Dados ficam no sandbox do app, sem backup automático: noBackupFilesDir Android, Application Support excluído de backup iOS e proteção de arquivo nativa. JSON versionado com escrita atômica e IO fora do thread principal; falha de leitura bloqueia gravação para não sobrescrever arquivo existente. Só mostrar salvo e fechar editor após escrita bem-sucedida. Falhas preservam rascunho; retry sem duplicata. Exclusão após confirmação explícita, sem cascades ou vínculos nesta coleção. Desinstalar/apagar dados pode remover ideias; sem recuperação/sync prometidos. Rascunho não confirmado é temporário, sem garantia após encerramento do processo.

Arquivos: modelos/testes core, repositório/estado e views nativas, Xcode/Gradle necessários, strings/backup rules, testes UI e scripts de captura, documentos de design/decisão/status/handoff/roadmap/índice/changelog. Lifecycle ViewModel AndroidX explícito para IO e estado; sem serviço ou framework de UI novo.

Aceite: preencher/validar/revisar/editar/cancelar sem perda involuntária; salvar e reabrir app mantendo ideia; confirmação de exclusão e retorno vazio; preservar contexto/puxador/temas. Testes de validação/Unicode, armazenamento round-trip/idempotência/corrupção e fluxo nativo nas duas plataformas. Capturas de home/editor padrão/compacto claro/escuro com dados sintéticos ou formulário vazio. Nada de dados pessoais reais em logs/CI/repositório.

Ameaças: endereço/nota podem conter dados pessoais; titular é quem usa o aparelho e finalidade é planejamento pessoal. Fronteira sandbox/disco, sem backend. Dados retidos até exclusão/desinstalação. Evitar logs de conteúdo, incluir rascunhos no backup ou sobrescrever arquivo ilegível. Salvaguardas: backup excluído, IO atômico/serializado, versão e entrada validadas, limite de arquivo 4MiB, erro explícito sem reset, proteção nativa, confirmação ao descartar/excluir.
