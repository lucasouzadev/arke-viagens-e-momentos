# ADR-009 — Início das duas bases nativas e verificação no GitHub Actions

**Data:** 31/10/2026 · **Status:** aceita para a fundação técnica delimitada abaixo, por instrução explícita no chat.

## Contexto e autorização

O responsável solicitou iniciar o desenvolvimento, priorizar iOS e Android juntos e usar GitHub Actions para compilar. O PR documental [#1](https://github.com/lucasouzadev/arke-viagens-e-momentos/pull/1) foi integrado em 28/10/2026, no commit `24007b08723ecf4df833ffc5b6a4e2ecc544c08b`.

## Decisão

- Autorizar a tarefa [M5-BOOTSTRAP-01](../engenharia/M5-BOOTSTRAP-01.md): projetos nativos SwiftUI e Compose, home inicial de dois cartões, estados transitórios de contexto/painel, testes e CI de verificação.
- Autorizar compilação Android de desenvolvimento e iOS Simulator sem assinatura, em runners padrão GitHub Actions; nenhum segredo de distribuição.
- A restrição documentation-first de ADR-005 e dos protocolos anteriores recebe **somente esta exceção**. Não significa aprovação automática de todas as propostas M1–M4.
- Os dois cartões começam com espaços explicitamente em desenvolvimento. Não simular mapa, viagem salva, sincronização ou recurso entregue.
- MapKit segue a direção iOS existente. Provedor Android, integração efetiva dos mapas, persistência, contas, grupos e política de offline seguem pendentes.
- O azul `#4C728A`, os identificadores `dev.arke.app.dev`, os targets mínimos iOS 17/Android 26 e a matriz de ferramentas são escolhas provisórias de engenharia para verificar esta fundação, sem definir marca ou identidade de loja.

## Limites e consequências

Sem assinatura de distribuição, upload de binários, TestFlight, loja, backend, migração, coleta de localização ou publicação de release. Merge continua dependendo do responsável. A licença final do projeto permanece pendente; não adicionar uma por suposição.

As duas plataformas compartilham semântica e critérios, não código de UI. Compilação/testes automatizados não comprovam acessibilidade, aparência ou funcionamento em dispositivo; esses gates permanecem explícitos.

## Alternativas consideradas

- Android primeiro: mais simples neste Windows, mas não atende à prioridade simultânea informada.
- Exigir Mac local para começar: desnecessário para CI de compilação; Mac/Xcode continuam necessários para desenvolvimento interativo iOS local.
- Framework híbrido: incompatível com ADR-001.
